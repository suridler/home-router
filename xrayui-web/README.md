# XrayUI Web

Непривилегированная панель home-router на Node.js и Express. Показывает состояние и отправляет типизированные запросы helper; не читает конфиг Xray напрямую и не выполняет привилегированные команды.

## Установка и доступ

Панель устанавливается [общим установщиком](../docs/INSTALLATION.md). По умолчанию адрес — `http://127.0.0.1:3000`. Параметры listener и `control_enabled` задаются в секции `[web]` helper, а не через `HOST`, `PORT` или `XRAYUI_CONTROL_ENABLED`.

Сервис работает как `xrayui-web` с доступом к Unix socket helper. Путь socket передаётся через `XRAY_CORE_HELPER_SOCKET` в runtime environment. Перед запуском listener панель получает настройки у helper; недоступные или некорректные настройки блокируют запуск.

HTTP-аутентификации пока нет. Для удалённого доступа используйте SSH-туннель; не публикуйте порт в интернет.

## Разработка

Нужен Node.js 18+ и доступ к работающему helper:

```bash
npm ci
npm test
npm start
```

`npm run test:integration` обращается к реальным сервисам; запускайте его только в рамках согласованной проверки хоста.

## Возможности

Панель содержит первичную настройку, общее состояние шлюза, маршрутизацию, outbounds, динамический список доменов и IPv4, geodata, журналы и управление разрешёнными сервисами. Сводка различает ошибки, выключенные компоненты и непроверенное состояние; при потере связи сохранённые данные помечаются устаревшими, изменения блокируются. Подтверждение временных сетевых настроек доступно во всех разделах. На главной доступны добавление записи в динамический список и последние события Xray с фильтром уровня и автообновлением; при недоступности источника сохранённые на странице события помечаются устаревшими. Раздел «Обновление системы» показывает установленную и последнюю версии, выполняет проверку, подготовку и установку с явными retry/rollback; во время активной установки и при recovery обычные изменения блокируются. Изменения контролирует helper; отключение web не влияет на data plane.

`GET /api/health` — агрегированная проверка, а не простая проверка Node listener. Во время первичной настройки helper может ещё не предоставлять нужную проекцию, поэтому этот запрос способен завершиться ошибкой при работающей странице. Установщик и ручная проверка listener используют `GET /`; подробнее — [диагностика](../docs/OPERATIONS.md).

Два графика показывают приём и передачу Xray по байтовым outbound-счётчикам отдельного exporter, без повторного суммирования inbound. Источник задаётся `[web].exporter_url` helper (по умолчанию `http://127.0.0.1:9101`, пустое значение отключает его). До двух свежих измерений и при недоступных/устаревших данных показывается отсутствие данных, а не нулевая скорость. Графики охватывают текущую сессию страницы. Вкладки настроек доступны напрямую по `#settings/system` и `#settings/logs`.

Настройка ротации файлов журналов по умолчанию сохраняется; включение или выключение требует явного выбора.

Единый блок «Журнал Xray» по умолчанию показывает пять последних ошибок из постоянного буфера helper на 100 записей. Одинаковые сообщения сохраняются отдельно, срок хранения не ограничен возрастом. Историю собирает внутренний планировщик helper каждые 20 с, а не systemd timer; info logging для этого не включается. Переключатели «Все события», «Предупреждения» и «Информация» показывают текущее окно журнала; оно опрашивается только при выбранном режиме событий. Источник, сбой и время сбора видны отдельно; подробности ограничений — в [архитектуре](../docs/ARCHITECTURE.md).

### Динамический список доменов и IPv4

На главной и в маршрутизации одно поле «Домен или IPv4» и действие «Добавить»;
примеры — `example.com` и `192.0.2.1`. Пользователь не выбирает тип вручную:
`POST /api/proxy-domains` отправляет поле `domain`, а `DELETE` использует тот же
path parameter. Проверку и нормализацию выполняет helper; панель не создаёт
собственного классификатора. IPv6, CIDR, URL и некорректный IPv4 отклоняются с сообщением; введённое
значение сохраняется в поле. Пустое поле не отправляется.

Успех показывает нормализованное значение `domain` из ответа helper, а не
исходную строку. Поле `applied` различает применение runtime и только
сохранённый desired: при `false` запись сохранена, но runtime ещё не изменён.
Подписи и счётчики используют «Домены и IPv4»/«Записи»; список показывает
фактическое значение и статус записи (динамическая, в основном списке, ожидает
удаления). Ожидающее удаление можно отменить. При успехе очищается только
отправленное значение; более новый ввод, набранный во время запроса, не
стирается.

Если ответ потерян, запрос завершился таймаутом или ошибка помечена
`mutationMayHavePersisted`, результат неизвестен: панель перечитывает список
через `GET /api/proxy-domains`, сохраняет предупреждение и ввод и не повторяет
POST/DELETE автоматически. Сбой этого чтения не превращает старые данные в
свежие и не отменяет предупреждение. При выключенном `[web].control_enabled`,
недоступном helper, update/recovery или safe-apply действуют существующие
блокировки; чтение не доказывает применение.

### Геобазы

На главной — последнее успешное обновление и следующий ежедневный запуск.
При ошибке ссылка «Подробнее» открывает этап, причину, результаты отдельных
файлов и ID для поиска записи в journal. Сбой запуска Xray отражается отдельно
в общем состоянии шлюза. Единое действие обновления пытается скачать внешние
и собрать пользовательские базы; успешный повтор снимает текущую ошибку.
Источники, лимит и расписание сохраняются helper в TOML; builder доступен
только для чтения и меняется вручную в TOML.
